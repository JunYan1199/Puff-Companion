# 从 0 开始指挥克劳德（Claude）构建帕芙模组实战手册

这份手册面向**零基础或第一次用 Claude Code 写 MC 模组**的流程，照着顺序一步步做就行。核心原则只有一句话：**不要让克劳德一口气写完，要拆成 5 个小关卡，每关进游戏亲眼验收通过再下一关。**

---

## 阶段 0：搭好空工程（大约 15 分钟）

### 1. 准备本地环境
* **JDK 17**（必须 17，不要装 21 或 8）。
* **Minecraft Forge 1.20.1 MDK**（去 Forge 官网下载 `1.20.1 - 47.2.x` 的 MDK 压缩包，解压到一个英文路径，比如 `D:\mc_mods\puff_companion`）。
* **前置模组 jar**（放到工程的 `libs\` 文件夹，没有就新建 `libs`）：
  * `Rats-Reboot-Forge-1.20.1-8.1.5.jar`（你已经有了）
  * 去 CurseForge/Modrinth 下载对应 `1.20.1 Forge` 版本的 **`Citadel`** 和 **`GeckoLib 4`**，也放进 `libs\`（或者让克劳德在 `build.gradle` 里配 Maven 依赖）。

### 2. 放好规范和人设文档
1. 把 `D:\老鼠\puff_npc_docs\CLAUDE.md` 复制到你的模组工程根目录（例如 `D:\mc_mods\puff_companion\CLAUDE.md`）。
2. 在工程里新建 `docs\` 目录，把 `D:\老鼠\puff_npc_docs\` 整个文件夹复制进去变成 `docs\puff_npc_docs\`。

### 3. 给克劳德发【第 0 条指令】
在你的工程目录打开 Claude Code，直接复制发送下面这段话：

> 请先阅读根目录的 `CLAUDE.md`。现在只做第 0 步：帮我把 Forge 1.20.1 空模组工程配置好。  
> 1. 修改 `build.gradle` 和 `META-INF/mods.toml`，把 modid 设为 `puffcompanion`（或我指定的名字），添加对 `rats`、`citadel`、`geckolib` 的依赖（`libs/` 里的 jar 用 `fg.deobf` 引入）。  
> 2. 写一个最简主类确认能注册。  
> 3. 运行 `./gradlew compileJava` 确保编译通过。  
> 完成这三步就停，不要提前写实体或剧情代码。

**验收标准**：`./gradlew runClient` 能成功启动游戏，在“Mods”列表里能同时看到你的模组和 `Rats: Reboot`。  
**立刻做一次 `git init && git add . && git commit -m "step0: base project"`**（以后每过一关都存个档，改坏了随时能回退！）。

## 阶段 1：让帕芙进游戏动起来（MVP 最小闭环）

先不搞剧情、不搞换装、不搞复杂 AI，先把**活的帕芙**放进游戏里。

### 发给克劳德的指令模板
> 请先阅读 `docs/puff_npc_docs/01_人设与阶段设定.md`。现在只做阶段 1（最小可玩实体）：  
> 1. 注册 `PuffEntity`（继承 `TamableAnimal`，接入 GeckoLib 4 `GeoEntity`），先用占位或基础素体模型（`.geo.json` + 贴图 + 基础 idle/walk 动画）。  
> 2. 添加核心数据同步与 NBT 持久化字段：`Affection`、`GrowthStage`、`CallMode`、`CurrentOutfit`、`PuffHunger`、`CompletedStories`。  
> 3. 实现“新世界创世第 1 天玩家首次出生并移动后，在玩家附近草丛自动生成 1 只帕芙并自动绑定主人”（用 World SavedData 保证每个存档只自然生成一次）。  
> 4. 添加最基础的跟随玩家与原地等待 AI。  
> 完成后运行 `./gradlew compileJava` 验证，不要写 GUI 和剧情系统。

**游戏内验收清单**：
* 新建一个存档，出生后走几步，草丛旁出现帕芙；
* 模型和贴图正常显示（不是紫黑块或隐身）；
* 她会跟着你跑，退出重进存档后她还在，且数据没重置。

---

## 阶段 2：打通“无 API 三层交互框架”

这一步要把“气泡、菜单、Galgame 对话窗”三条管道都接通，但每条只放 1~2 个测试例子。

### 2A. 先做头顶气泡 + 4 个核心事件触发器
> 现在只做“本地事件气泡与聊天栏播报系统”：  
> 1. 建立客户端 `PuffBubbleRenderer`，能在帕芙头顶渲染带圆角底框的简短中文气泡（支持 `{player}` / `{call}` 占位符自动替换）。  
> 2. 建立服务端→客户端发包 `PuffBubblePacket`。  
> 3. 先接入 4 个触发器测试（带冷却时间）：12格内有苦力怕预警、8格内有猫/豹猫炸毛躲身后、玩家手里拿奶酪眼冒金光、空手 Shift+右键摸头触发害羞当机台词。  
> 台词先用 `zh_cn.json` 语言键管理。完成后编译检查。

### 2B. 再做右键交互菜单（`InteractionScreen`）
> 现在做右键帕芙打开的交互界面 `PuffInteractionScreen`：  
> 1. 显示帕芙当前名字、好感度、阶段、饱食度与当前服装。  
> 2. 左侧放固定话题按钮（先接通“关于你自己”和“关于其他小老鼠”2 个话题）。  
> 3. 右侧放功能按钮：赠送主手物品（按奶酪/闪亮物/普通物分级加好感与回话）、切换跟随/等待/坐下/坐肩膀、摸头互动、换装按钮（先留接口）。  
> 所有按钮操作必须通过 Forge `SimpleChannel` 发包给服务端校验并持久化，不要只在客户端改数值。

### 2C. 最后做 Galgame 剧情演出界面（`DialogueScreen`）并跑通《序章》
> 请阅读 `docs/puff_npc_docs/02_主线与支线剧情脚本.md` 的《序章》。现在实现本地 Galgame 剧情界面 `PuffDialogueScreen`：  
> 1. 剧情数据从 `data/puffcompanion/puff_stories/prologue.json` 读取，支持角色名、表情标签、逐字显示、2 个选项分支与好感/状态结算。  
> 2. 在帕芙出生后自动触发《序章》，选完选项后记录 `puff_story_prologue` 为已完成，刷新后不再重复弹出。  
> 完成后编译并给出测试命令（比如加一个调试指令 `/puff story <id>` 方便我直接重看和测试剧情）。

**游戏内验收清单**：见到苦力怕/猫/奶酪会冒气泡，右键菜单能送礼摸头，新建世界能弹出《序章》并选分支加好感。

## 阶段 3：`Rats: Reboot` 深度联动 + 花枝鼠专属 AI

### 发给克劳德的指令模板
> 在引用 `rats` 任何类之前，请先用 `javap -cp libs/Rats-Reboot-Forge-1.20.1-8.1.5.jar ...` 确认真实包名与方法签名。现在实现与 `Rats: Reboot` 的联动和花枝鼠习性：  
> 1. 识别 `rats:cheese` 等奶酪物品与方块，闻到奶酪会触发理智清零气泡并大幅回满饱食度与好感。  
> 2. 扫描周围属于同一主人的 `Rat` 实体：当附近小老鼠完成收割/搬运或处于工作状态时，定期触发帕芙“大姐头讨工资”气泡，此时送奶酪或摸头有额外好感加成。  
> 3. 添加花枝鼠“秘密小窝囤积 AI”：空闲时自动捡起地面掉落的粒/粉尘/种子/奶酪碎屑存入帕芙专属 `HoardInventory`（可在菜单查看）。  
> 4. 识别 `PlagueDoctor` 实体与 `rats:ratlantis` 维度，触发对应专属台词。

## 阶段 4：灌注全部剧情、台词库与 5 套阶段换装

等前三步全部稳如老狗之后，这一步纯属“填内容”，克劳德做起来又快又稳：

### 发给克劳德的指令模板
> 请对照 `docs/puff_npc_docs/02_主线与支线剧情脚本.md` 和 `03_交互菜单与事件触发对话库.md`，补全剩余全部内容：  
> 1. 把第 1~3 章、支线 1~2、终章结婚、婚后番外全部转为 `data/puffcompanion/puff_stories/*.json`，并接入各自的触发条件检查器（阶段、好感、群系、维度、猫实体、求婚信物）。  
> 2. 把 `03` 文档中的所有随机台词池和四阶段差异化台词补全到 `assets/puffcompanion/lang/zh_cn.json`。  
> 3. 接入 5 套阶段服装切换逻辑（`early` / `mid` / `late` / `swim` / `wedding`），剧情解锁后可在交互菜单自由切换。

## 指挥克劳德的 5 条黄金避坑法则

1. **报错直接全贴，不要只截最后一行**：遇到编译或崩溃，把完整的 `latest.log` 或报错堆栈直接丢给它，说一句“修好这个报错并重新编译”。
2. **禁止它“顺便重构”无关代码**：如果某一步写歪了，直接用 `git checkout` 回退，重新给更小的任务，别让它在错的代码上越补越乱。
3. **模型与代码分离**：你自己在 Blockbench / `geckolib-base-body` 里调模型时，提前把 5 套衣服的骨骼组名字和贴图路径告诉克劳德，让它按你的名字写渲染代码。
4. **必须留调试指令**：一定要让克劳德从阶段 2 就加好 `/puff debug affection <数值>`、`/puff debug stage <1-4>`、`/puff debug story <id>` 这类管理员调试命令，不然你测结婚剧情难道真的每次重肝 10 小时生存吗！
5. **每次验收完就 Git Commit**：每过一个小阶段立刻提交一次 Git，这是你最强的后悔药。
